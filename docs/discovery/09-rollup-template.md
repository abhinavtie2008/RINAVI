# Rollup template

**Status:** draft instrument, 2026-11-24. Twenty minutes after every fifth
session, and once at the end. This is what stops discovery becoming a folder of
notes nobody reads.

## 1. Friction inventory

One row per tag × step. Counted, not summarised.

| Tag | Step | Sessions (n) | BLOCKER | MAJOR | MINOR | Assistable YES / POLICY / NO |
|---|---|---|---|---|---|---|
| `PROVE` | `GATHER` | | | | | |
| `RETRY` | `CORRECT` | | | | | |

Rules: a tag with one session is labelled *single case* in the report; do not
merge tags to make a row bigger; and do not count a session twice for the same
tag on the same step — the unit is the session, not the mention.

## 2. Quote bank

| Quote (verbatim) | P-code | Quotes consent | Theme |
|---|---|---|---|
| "…" | P07 | yes | comprehension |

Every quote here must have a yes in the consent column. A quote without one is
deleted, however good it is.

## 3. Decision ledger — the part that matters

A finding that does not change a decision is a paragraph. Each row ends in one
of four outcomes.

| # | Finding | Evidence | Decision | Owner | Status |
|---|---|---|---|---|---|
| F-01 | Father's-name mismatch rejected seven of twenty | P03, P07, P09, P11, P14, P17, P19 | **Change product**: consistency check between a field and the document carrying it | Product (YooExE's queue) | Open |
| F-02 | Agent did the upload for nine of twenty | P01, P04, … | **Change scope question**: is the value comprehension or convenience? Owner decision, no code | Founder | Open |
| F-03 | Two participants could not follow the English consent form | P12, P18 | **Defer**: Hindi layer (item 100), evidence for its priority | Founder | Recorded |
| F-04 | Department waits of 3–5 weeks | eight sessions | **Reject as product work**: `NO` — context for expectations, not a task | — | Closed |

Four outcomes, and every row picks one: **change product**, **change the study**,
**change scope (owner decision)**, or **reject with a reason**. "Noted" is not an
outcome.

## 6. The public report — eight headings

`docs/evaluation/discovery-findings-YYYY-MM-DD.md`, category level, no
participant data:

| Heading | Must contain |
|---|---|
| What was done | Sessions, dates, channels, language split, who ran them |
| Who was heard | The mix actually achieved, and the shortfall against 02 |
| The demand baseline | 07's measures, each with `n` |
| Where it breaks | The friction inventory, ranked by sessions × severity |
| What it costs | Time, trips, money, agent share — bands and medians |
| The manual baseline | The median, the runs, the covariate, the exclusions |
| The scorecard and the selection | The ranking, the citations, the disqualifiers, what would change it |
| Limits | One coder; twenty sessions; one city; no real application observed; what this cannot support |

## 7. Weekly rhythm

| When | Do |
|---|---|
| After each session | Note and code (05), same day |
| After every fifth | Update §1 and §2; check the mix against 02 and recruit the lagging row |
| At session 10 | Score the candidates once (06) — early enough to expose a criterion with no evidence |
| At session 20 | Finalise §1–§5, run 07's manual baseline, draft the report |
| At close | E1–E8 in 08, publish, tick item 82, hand the blocker rows to the product queue |

## The one rule

**Every number carries its `n`.** "Most participants" is not a finding;
"14 of 20, self-applied group, all in Delhi" is. The report will be read by
someone deciding whether to spend six months on the next service, and they will
check the denominator before they read the story.
